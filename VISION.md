# numerical.run — architecture

One `.nb.md` document, one RunMat WASM kernel, two modes over it — a **notebook**
for building and an **app** for using. Everything runs client-side in the browser.

## The kernel

The RunMat runtime compiled to WebAssembly, driven over the Jupyter messaging
protocol (`execute_request` / `execute_reply`, `stream`, `status`). One session
backs every surface — the notebook cells and the app render alike. Because the
boundary is the Jupyter protocol, the kernel isn't numerical.run-specific.

`kernel.js` exposes two entry points:

- **`runCell(cell)`** — execute one cell against the current workspace, no reset.
  Variables persist across calls, so cells are stateful (Jupyter-style). This is
  the notebook's per-cell Run.
- **`runAll(cells)`** — reset the session, then run every code cell top-to-bottom.
  This is the app's whole-document rerun (Streamlit-style) on every interaction.

A single-flight lock serializes executes (the WASM session is single-threaded).

## Widgets

Widgets are the **`nr_*`** library (`lib.m`): plain user-space MATLAB functions
(`nr_slider`, `nr_selectbox`, `nr_button`, `nr_metric`, `nr_figure`, …) that print
one marker line to stdout,

```
%%NR%%{...json...}
```

which the host parses into elements and renders (`render.js`). No runtime, parser,
or syntax changes — `v = nr_slider('freq', 1, 8, 2)` is an ordinary call whose
side effect is a marker. Widget **state** survives a rerun by being baked back
into the generated source as a `jsondecode` literal (`nr_state_`, regenerated by
the host each run) — the simplest reliable channel given RunMat's constraints.

## The `.nb.md` format

A Markdown-based Jupyter notebook following
[JEP&nbsp;#103](https://github.com/jupyter/enhancement-proposals/pull/103):
narrative Markdown split by `+++`, and code cells as fenced
` ```matlab {jupyter.code-cell} ` blocks whose leading `:key: value` lines carry
cell metadata. numerical.run's own widget/layout data rides in that metadata
(`:widget:`), so a `.nb.md` is a plain Markdown Jupyter notebook to any
JEP-103-aware tool, human-diffable and one-hunk-per-cell in git. `.ipynb` stays a
supported interop export; `.nb.md` is the working format.

## The single-page app

State lives in the URL. The **editor** is chosen by `?editor=notebook` (default,
the notebook-as-editor) or `?editor=classic` (one Monaco over the whole document
plus an App preview) — URL-only, no toggle button. The **Notebook | App** control
switches authoring vs. the rendered app. The document arrives via
`#code=<base64>` / `?code=` / `?gist=<id|raw-url>`, else a built-in default. Cells
can be inserted anywhere via an always-visible `+` (Code / Text / Widget).

## Inspirations, named honestly

- **Streamlit** — "the script is the app," whole-document rerun (App mode).
- **Jupyter** — the kernel protocol both modes speak; `.ipynb` interop.
- **[JEP #103](https://github.com/jupyter/enhancement-proposals/pull/103)** — the
  Markdown-notebook spec `.nb.md` adopts.
- **Jupytext / MyST-NB / Quarto** — prior art for Markdown ⇄ notebook.
- **marimo / Pluto.jl** — reactive notebooks; the insert-anywhere and cell UX.
