# numerical.run × Jupyter

Run numerical.run `.nb.md` notebooks in the Jupyter ecosystem, on the **RunMat**
kernel — in the browser (JupyterLite) or on a server (JupyterLab).

## What's here

- `nbmd2ipynb.mjs` — convert a `.nb.md` to `.ipynb` (tagged with the `runmat`
  kernelspec). Pairs with the web app's existing `.ipynb` → `.nb.md` importer, so
  notebooks move both ways.
- `notebooks/` — numerical.run notebooks as `.ipynb` (regenerated by the build).
  `numerical-run.ipynb` is a plain-MATLAB demo that runs today.
- `lite/` — JupyterLite deployment config (`jupyter-lite.json` points the RunMat
  kernel at the bundled WASM runtime).
- `build-lite.sh` / `serve.sh` — build and serve the JupyterLite site locally.

## Build & serve (JupyterLite)

The RunMat Jupyter kernel comes from the `runmat-jupyter` project (its venv has
the `jupyterlite-runmat-kernel` labextension enabled). Point at it if it lives
elsewhere via `RUNMAT_JUPYTER=/path`.

```bash
./build-lite.sh          # → jupyter/lite/_output
./serve.sh               # → http://127.0.0.1:8123/lab/index.html
```

Open `numerical-run.ipynb`, pick the **RunMat** kernel, Run All — you get a
damped-sine figure and echoed values, all client-side.

## JupyterLab (server)

The same kernel installs as a native kernelspec (`runmat`) from the
`runmat-jupyter` project:

```bash
/root/Projects/runmat-jupyter/.venv/bin/jupyter lab jupyter/notebooks
```

Select the **RunMat** kernel and run any notebook here.

## Note on `nr_*` widgets

Notebooks that use numerical.run's `nr_*` widgets (sliders, metrics, heatmaps)
depend on numerical.run's renderer, which Jupyter doesn't have yet — those cells
print raw `%%NR%%` markers on the generic RunMat kernel. The plain-MATLAB demos
run fully. Widget rendering inside Jupyter outputs is the phase-2 item in the
tracking issue.
